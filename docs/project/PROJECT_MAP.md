# Project Map – Kotodama

High-level tour of the repository, updated for the reply-only product.

---

## 1. Directory Overview

```
kotodama/
├── README.md                 # User-facing overview
├── docs/                     # Documentation hub (guides, reference, project notes)
├── package.json              # Scripts, dependencies, release metadata
├── public/                   # Manifest + static icons (PNG required before publishing)
├── scripts/                  # Build helpers (copy manifest/icons, generate assets)
├── src/                      # All extension source code
│   ├── api/                  # AI provider clients (OpenAI, Gemini, Claude) + vision pass
│   ├── background/           # Manifest V3 service worker
│   ├── components/           # Shared React components
│   ├── constants/            # Model metadata, reply templates
│   ├── content/              # Twitter/X DOM integration + shadow-root host
│   ├── hooks/                # Shared React hooks
│   ├── onboarding/           # First-run setup flow
│   ├── panel/                # Reply composer UI (mounted inside the content script)
│   ├── settings/             # Settings dashboard + brand voice manager
│   ├── storage/              # IndexedDB schema + encryption helpers
│   ├── styles/               # Global CSS + token definitions
│   ├── types/                # Shared TypeScript interfaces
│   └── utils/                # Sanitization, rate limiting, runtime messaging, logging
└── dist/                     # Build artifacts (created by `npm run build`)
```

### `src/` Highlights

| Path | Purpose |
|------|---------|
| `api/openai.ts` | OpenAI client **plus** the shared `buildSystemPrompt` / `buildUserPrompt` used by all providers |
| `api/gemini.ts`, `api/claude.ts` | Gemini and Claude clients — both wired through the service worker |
| `api/vision.ts` | Context-reading pass: reads the tweet + up to 4 images with a fixed cheap vision model |
| `background/service-worker.ts` | Message router, provider dispatch, storage access, rate limiting |
| `content/content-script.tsx` | Injects the shadow-root host + floating button, captures reply context, inserts the draft |
| `panel/Panel.tsx` | Reply composer (context card, intent box, tone/length controls, result carousel) |
| `settings/App.tsx` | Settings dashboard state management and sidebar navigation |
| `settings/components/BrandVoicePage.tsx` | Dashboard view for brand voice CRUD |
| `onboarding/Onboarding.tsx` | Multi-step setup flow with Split Layout |
| `storage/db.ts` | Dexie schema for voices, history, user profiles |
| `storage/settings.ts` | Chrome storage wrapper with encryption |
| `utils/sanitize.ts` | Trust boundary for everything scraped off the page before it reaches a prompt |

## 2. Build Output Snapshot (`dist/`)

Generated by `npm run build` (or `npm run dev` in watch mode).

```
dist/
├── background.js         # Service worker bundle
├── content.js            # Content script + panel, single IIFE (second Vite pass)
├── onboarding.js         # Onboarding UI
├── settings.js           # Settings/brand voice manager UI
├── index.css             # Compiled Tailwind styles for the extension pages
├── manifest.json         # Copied from public/
├── icons/                # Copied from public/icons/
└── src/
    ├── onboarding/index.html
    └── settings/index.html
```

Shared chunk names vary with the bundler; the four entry bundles above are the stable ones.
There is no `panel.js` or `src/panel/index.html` — the panel ships inside `content.js`.

## 3. Runtime Data Flow

```
Twitter/X Page
    └─ content-script.tsx injects #kotodama-host + shadow root + sparkle button
        └─ Click → capture the tweet being replied to (text, author, images, thread)
            └─ Panel.tsx mounts in the shadow root with that context
                ├─ chrome.runtime.sendMessage({ type: 'analyze-context' })
                │   └─ service-worker.ts → api/vision.ts
                │       └─ 1-3 plain sentences shown in the context card
                └─ chrome.runtime.sendMessage({ type: 'generate' })
                    └─ service-worker.ts
                        ├─ Rate-limit check
                        ├─ Loads settings (encrypted key, default provider/model)
                        ├─ Fetches brand voice from IndexedDB
                        └─ Calls OpenAI / Gemini / Claude
                            └─ Receives draft → saves history (optional)
                └─ Panel renders drafts in a carousel
                    └─ User clicks Insert
                        └─ onInsert prop → content script writes into the compose box
```

Key points:
- All data stays local except outbound HTTPS calls to the selected AI provider (and `pbs.twimg.com` image fetches for the vision pass).
- The product is reply-only: with no readable tweet in view the panel renders an empty state rather than falling back to a compose flow.
- The vision summary is an enhancement, never a gate — a failed read degrades to text-only and generation still works.
- Generation history writes to IndexedDB only if `rememberHistory` is enabled.

## 4. Storage & Settings

| Storage | Contents |
|---------|----------|
| IndexedDB (`src/storage/db.ts`) | Brand voices, optional generation history, cached user profiles |
| Chrome storage (`src/storage/settings.ts`) | Encrypted API keys, UI preferences, default provider/voice/model, floating button position, rate-limit window |

Encryption uses Web Crypto (AES-GCM) before persisting values. Keys are decrypted only inside the service worker.
